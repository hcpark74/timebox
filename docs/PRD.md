# Timebox Flow PRD

## 1. 제품 개요

Timebox Flow는 많은 할 일 중 오늘 반드시 실행할 핵심 3~4개를 고르고, 이를 정해진 시간 블록에 배치해 하루를 운영하도록 돕는 데일리 타임박스 플래너입니다.

이 제품은 복잡한 프로젝트 관리 도구가 아니라, 현재 구현된 모바일 중심 UI를 바탕으로 `할 일 목록 -> 오늘의 핵심 -> 시간 배치 -> 오늘 일정` 흐름을 빠르게 실행하게 만드는 개인 생산성 도구를 목표로 합니다.

## 2. 제품 목적

- 백로그에 쌓인 많은 할 일 때문에 우선순위를 못 정하는 문제를 줄인다.
- 하루에 처리할 핵심 3~4개만 선택하게 만들어 결정 피로를 낮춘다.
- 정해진 시간 블록에 과업을 넣어 실행 중심의 하루를 만든다.
- 퇴근 전 버퍼 시간을 따로 두어 일정 밀림을 흡수한다.

## 3. 핵심 가치

- 결정 피로 감소: 오늘 할 일을 제한된 개수로 선택
- 실행 중심 단순함: 복잡한 설정보다 빠른 선택과 배치
- 시간 블록 기반 집중: 하루를 큰 덩어리의 집중 구간으로 운영
- 현실적인 유연성: 마지막 버퍼 블록으로 계획 붕괴 완화

## 4. 타깃 사용자

- 하루 업무를 직접 설계하고 실행하려는 개인 사용자
- 학생, 직장인, 프리랜서, 1인 사업자
- 협업 툴보다 개인 실행 플래너를 원하는 사용자
- 하루 백로그는 많지만 실제로는 3~4개의 핵심 일에 집중하고 싶은 사용자

## 5. 핵심 사용자 워크플로우

### 1) 할 일 목록 정리

- 사용자는 생각나는 할 일을 `할 일 목록`에 10개 내외로 모아둔다.

### 2) 오늘의 핵심 선택

- 사용자는 `할 일 목록`에서 오늘 반드시 할 핵심 3~4개를 골라 `오늘의 핵심`으로 옮긴다.

### 3) 시간 블록 배치

- 사용자는 오늘의 핵심 과업을 정해진 시간 블록에 배치한다.
- 기본 블록은 다음과 같다.
  - `09:00 - 11:30` 핵심 작업 1
  - `13:00 - 15:00` 핵심 작업 2
  - `15:00 - 17:00` 핵심 작업 3
  - `17:00 - 18:00` 버퍼 / 정리 / 밀린 일 처리

### 4) 실행

- 사용자는 `오늘 일정` 화면을 보며 현재 블록에 해당하는 작업에 집중한다.
- 작업이 끝나면 완료 상태를 체크한다.

### 5) 검토

- 사용자는 하루가 끝난 뒤 완료 여부를 확인하고, 남은 일은 다음 날 다시 `할 일 목록` 또는 `오늘의 핵심`으로 조정한다.

## 6. 현재 UI와 제품 구조 매핑

- `할 일 목록`: 후보 할 일 목록
- `오늘의 핵심`: 오늘 실행할 핵심 3~4개
- `시간 배치`: 시간 블록 배치 화면
- `오늘 일정`: 오늘 실행 화면
- `캘린더`: 날짜별 배치 확인 화면
- `내 정보 / 통계`: 개인 요약 및 향후 확장 영역

## 7. 기능 요구사항

### A. 할 일 목록 관리

- 사용자는 빠르게 새 할 일을 추가할 수 있어야 한다.
- 사용자는 불필요한 할 일을 삭제할 수 있어야 한다.
- 사용자는 할 일 목록에 여러 개의 후보 작업을 보관할 수 있어야 한다.

### B. 오늘의 핵심 선정

- 사용자는 `할 일 목록`의 작업을 `오늘의 핵심`으로 이동할 수 있어야 한다.
- 사용자는 오늘 집중할 핵심 작업 수를 3~4개 수준으로 유지할 수 있어야 한다.
- 사용자는 `오늘의 핵심`과 `할 일 목록` 사이를 쉽게 오가며 조정할 수 있어야 한다.

### C. 시간 블록 스케줄링

- 사용자는 `오늘의 핵심`의 작업을 시간 슬롯에 드래그해 배치할 수 있어야 한다.
- 기본 경험은 자유 배치가 아니라 정해진 주요 블록을 중심으로 사용되도록 유도해야 한다.
- 마지막 블록은 버퍼 블록 성격으로 사용할 수 있어야 한다.
- 사용자는 선택한 날짜 기준으로 배치를 초기화할 수 있어야 한다.

### D. 실행 및 완료 처리

- 사용자는 `오늘 일정`에서 배치된 작업을 시간순으로 확인할 수 있어야 한다.
- 사용자는 완료 여부를 즉시 토글할 수 있어야 한다.
- 완료 상태는 저장되어 다시 접속해도 유지되어야 한다.

### E. 검토 및 요약

- 사용자는 카테고리별 태스크 수를 확인할 수 있어야 한다.
- 사용자는 향후 오늘 완료 수, 스케줄 대비 완료율, 버퍼 활용 정도를 확인할 수 있어야 한다.

### F. 저장 및 동기화

- 앱은 기본적으로 `localStorage`에 데이터를 저장해야 한다.
- 새로고침 후에도 데이터가 유지되어야 한다.
- 선택적으로 동기화 ID 기반 기기 간 동기화를 지원할 수 있어야 한다.

## 8. 비기능 요구사항

- 모바일 화면에서 한 손으로 주요 흐름을 수행할 수 있어야 한다.
- 드래그 앤 드롭이 즉각적으로 반응해야 한다.
- 네트워크가 없어도 기본 UI와 로컬 데이터는 사용 가능해야 한다.
- 복잡한 설정 없이 바로 쓸 수 있어야 한다.

## 9. MVP 범위

### 포함

- 할 일 목록 태스크 추가/삭제
- `오늘의 핵심`과 `할 일 목록` 간 이동
- 스케줄링 화면에서 작업 배치
- 타임라인 확인 및 완료 처리
- 날짜별 일정 조회
- 기본 로컬 저장

### 제외

- 세밀한 타이머 기능
- 푸시 알림
- AI 자동 배치
- 캘린더 외부 연동
- 협업 기능

## 10. 성공 기준

- 사용자가 할 일 목록에서 오늘의 핵심 3~4개를 쉽게 고를 수 있다.
- 사용자가 하루 블록에 작업을 배치한 뒤 바로 실행에 들어갈 수 있다.
- 사용자가 완료/미완료를 기준으로 하루를 마무리할 수 있다.
- 사용자가 앱을 복잡한 투두앱이 아니라 실행용 플래너로 인식한다.

## 11. 향후 확장

- `통계` 탭 추가 및 계획 대비 완료율 시각화
- 버퍼 블록 사용 빈도 분석
- 일일 회고 메모
- 카테고리/우선순위 입력 UX 개선
- Sync 안정성 개선
- 반복 일정 및 외부 캘린더 연동
