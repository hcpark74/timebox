# Timebox Flow Roadmap

## 목적

이 문서는 현재 Timebox Flow를 `계획 -> 배치 -> 실행 -> 마무리` 흐름이 자연스럽게 이어지는 데일리 플래너로 발전시키기 위한 우선순위 로드맵입니다.

현재 방향은 기능을 많이 늘리는 것보다, 이미 구현된 핵심 흐름을 더 완결된 사용자 경험으로 만드는 데 있습니다.

## 현재 상태

- `할 일 정리`: 오늘의 핵심 선택, 수동 재정렬, 목록 접기 가능
- `시간 배치`: 주간 날짜 이동, 고정 블록 카드 기반 배정/해제 가능
- `오늘 일정`: 배정 결과 확인, 완료/해제 가능
- `캘린더`: 주간 날짜 선택과 일정 확인 가능
- `내 정보`: 동기화 ID 복사/수정, 카테고리 수 확인 가능

## 1단계 - 핵심 흐름 완성

### 1. 하루 마무리 흐름

- 완료 / 미완료 작업을 하루 끝에서 분리해 보여주기
- 미완료 작업을 다음 날 핵심 후보나 할 일 목록으로 넘기는 흐름 추가
- 버퍼 블록에서 처리된 작업까지 자연스럽게 정리할 수 있게 만들기

이유:

- 지금 제품은 `계획 -> 배치 -> 실행`까지는 거의 완성됐고, `마무리`만 비어 있음
- 하루를 닫는 경험이 생겨야 반복 사용성이 올라감

### 2. QA 체크리스트 정리

- 핵심 화면별 수동 점검 체크리스트 문서화
- 새로고침, 날짜 이동, 배정, 완료 처리 회귀 확인 기준 정리

이유:

- 최근 UI 구조 변경이 많아 다음 작업 전에 안정성 기준이 필요함

### 3. 문서 최신화 마감

- `README.md`, `MANUAL.md`, `BackLog.md`의 최신 흐름 반영 상태 점검
- `시간 배치` 단순화와 하단 탭 변경 기준으로 문서 정합성 맞추기

## 2단계 - 사용자 가치 확장

### 4. 통계 화면 MVP

- 오늘 완료 수
- 오늘 배정 수
- 계획 대비 완료율
- 주간 활동 정도

이유:

- 이미 있는 통계 API를 실제 사용자 화면으로 연결할 수 있음
- 실행 결과를 되돌아보는 최소 기능이 됨

### 5. 카테고리 / 우선순위 입력 개선

- 새 태스크 생성 시 카테고리 선택 추가
- 필요 시 성격 태그나 우선순위 입력 보강
- `개인`, `업무`, `회의` 같은 실제 사용 분류 강화

이유:

- 현재 데이터 구조는 있지만 입력 경험이 단순함
- 통계와 필터 기능의 기반이 됨

### 6. 동기화 안정성 개선

- 마지막 수정 시각 저장
- 덮어쓰기 기준 정의
- 충돌 시 안내 문구 또는 선택 흐름 추가

이유:

- 여러 기기 사용 시 현재 구조는 충돌에 약함
- 실사용 안정성을 올리려면 필수임

## 3단계 - 확장 기능

### 7. 검색 기능

- 태스크 제목 검색
- 상태 / 카테고리 기준 필터

### 8. 반복 일정

- 매일 / 매주 반복 작업 생성
- 반복 규칙 기반 기본 후보 자동 생성

### 9. 알림 기능

- 브라우저 알림 또는 로컬 알림
- 핵심 블록 시작 전 리마인드

### 10. 외부 캘린더 연동

- Google Calendar 등 외부 일정 읽기
- 고정 블록과 외부 일정 충돌 확인

### 11. 고급 분석

- 주간 완료 패턴
- 시간 블록별 완료 성과
- 계획 대비 실행률 변화

## 추천 진행 순서

1. 하루 마무리 흐름
2. QA 체크리스트
3. 통계 화면 MVP
4. 카테고리 / 우선순위 입력 개선
5. 동기화 안정성 개선

## 판단 기준

- 새 기능보다 반복 사용 흐름을 더 매끄럽게 만드는가
- 사용자가 하루 계획을 더 빨리 세우고 마무리할 수 있는가
- 최근 UI 단순화 방향과 충돌하지 않는가
